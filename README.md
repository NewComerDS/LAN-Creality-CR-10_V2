# cp81 - Подключение «старого» принтера на Marlin к Creality Print 7.x по сети (проверено: CR-10 V2)

Creality Print 7.1+ умеет работать по локальной сети со старыми принтерами Creality (через WiFi-box), но «голый» CR-10 V2
этот протокол не понимает. **cp81 прикидывается таким принтером**: небольшая служба на Python на Raspberry Pi / Orange Pi,
подключённой к принтеру по USB, переводит команды Creality Print в G-code для Marlin.

<img width="1591" height="849" alt="2026-10-08 122314" src="https://github.com/user-attachments/assets/82df7ba3-efc8-454a-9987-3b3c6976e6d1" />

```
Creality Print (ПК) --HTTP :81--> cp81.py ----USB serial----> CR-10 V2 (Marlin)
                    --FTP  :21--> cp81_ftp.py (загруженный G-code лежит в ./ftp_root, cp81.py печатает его построчно)
                    (камера: необязательный MJPEG-поток на :8080, запускается отдельно)
```

> **Неофициальный проект.** Не связан с Creality и не одобрен ею. Кода Creality в репозитории нет; заметки о протоколе
> ниже получены наблюдением за сетевым трафиком и за поведением программы.

## Что работает

* принтер появляется в Creality Print, живые температуры, целевые температуры, позиция, вентилятор вкл/выкл
* хоуминг, перемещение осей, температура сопла и стола, скорость печати, вентилятор
* загрузка G-code, список файлов и удаление прямо из Creality Print (собственный небольшой FTP-сервер)
* **печать с хоста**: файл G-code отправляется в принтер по serial построчно; прогресс и оставшееся время в Creality Print,
  пауза / продолжение / стоп, проверки безопасности и обработка аварий (см. ниже)

## Безопасность - прочитай в первую очередь

Печать с хоста означает, что **за нагревом во время печати отвечает эта программа**.

* Не оставляй печать без присмотра, особенно первые. Настоящий аварийный стоп - выключатель питания принтера; кнопка
  *стоп* в Creality Print ждёт окончания текущей строки G-code (например, хоуминга).
* Если Pi зависнет или USB-кабель отвалится во время печати, принтер остановится на месте, а нагрев останется включённым
  (его контролирует только штатная термозащита Marlin). Перезапуск службы перезагружает плату принтера и обрывает печать.
* Ограничения на стороне хоста: сопло <= 260 C, стол <= 90 C, ходы внутри стола, список разрешённых G-кодов, запрещённые коды
  (`M500`, `M112`, `M81` и др.). Для своего принтера поправь константы в начале `cp81.py`.
* Предполётная проверка перед каждой печатью (температуры, разрешённые коды, координаты, `G28`). Без `--print-enable`
  команда `print` - только пробный прогон.
* Всё на твой страх и риск (см. отказ от гарантий в LICENSE).

## Требования

* Creality Print 7.1 (Windows), принтер с Marlin и USB serial (115200 бод)
* небольшой Linux-компьютер рядом с принтером, Python 3.9+, `pyserial`
* ПК и Linux-компьютер в одной сети; мост слушает порт 81, FTP-сервер - порт 21 (нужен root)

## Быстрый старт

```bash
sudo apt install python3-serial           # или: pip install -r requirements.txt
sudo mkdir -p /opt/cp81 && sudo cp cp81.py cp81_ftp.py /opt/cp81/ && cd /opt/cp81

# 1) только чтение: температуры и позиция, в принтер уходит лишь M105/M114
python3 cp81.py --serial /dev/ttyUSB0 --allow 127.0.0.1,<IP ПК>
```
В Creality Print добавь устройство **по IP-адресу** (адрес Linux-компьютера). Оно должно появиться как CR-10.

```bash
# 2) управление: хоуминг, перемещения, температуры (открытие serial-порта перезагружает плату принтера)
python3 cp81.py --serial /dev/ttyUSB0 --allow 127.0.0.1,<IP ПК> --live

# 3) загрузка файлов: FTP-сервер (для порта 21 нужен root), загрузи файл из Creality Print
sudo python3 cp81_ftp.py --root ./ftp_root --allow 127.0.0.1,<IP ПК> --verbose

# 4) печать: сначала тестовый файл без нагрева examples/air_test.gcode, со ПУСТЫМ столом и стоя рядом с принтером
python3 cp81.py --serial /dev/ttyUSB0 --allow 127.0.0.1,<IP ПК> --live --print-enable
```
Обе программы должны использовать одну и ту же папку (`--ftp-root` у `cp81.py` = `--root` у `cp81_ftp.py`; по умолчанию `./ftp_root`).
Автозапуск: `systemd/*.service` (поправь пути и IP, затем `systemctl enable --now`).

### Параметры

| `cp81.py` | |
|---|---|
| `--serial DEV` | serial-порт принтера (для стабильного имени используй `/dev/serial/by-id/...`) |
| `--allow IPS` | IP клиентов через запятую, по умолчанию только `127.0.0.1` |
| `--ftp-root DIR` | где ищутся загруженные файлы G-code |
| `--live` | реально отправлять команды (без него всё только пишется в лог) |
| `--print-enable` | `print=` действительно печатает; нужен `--live` |
| `--home-on-start` | один `G28` после первого подключения (нужен `--live`) |
| `--verbose` | писать в лог каждый опрос от Creality Print |

`cp81_ftp.py`: `--root`, `--allow`, `--port`, `--max-upload-mb`, `--list-style`, `--verbose`.

## Заметки о протоколе (как уговорить Creality Print)

* **Обнаружение / статус**: `GET :81/protocal.csp?fname=Info&opt=main&function=get`, примерно раз в 5 с, ответ - JSON.
  `model` должен быть именем, для которого в Creality Print есть пресет (`"CR-10"`; с `"CR-10 V2"` ломались кнопки осей),
  `ssid` - `CR10-<12 шестнадцатеричных цифр>`.
* **Поля Info**: `nozzleTemp`/`bedTemp` (текущие), `nozzleTemp2`/`bedTemp2` (целевые), `curPosition`
  (`"X:.. Y:.. Z:.."`), `autohome` (0/1), `curFeedratePct`, `fan` (0/1 - любое ненулевое значение показывается как 100 %),
  `printProgress`, `printLeftTime` и `printJobTime` (секунды), `print` (путь к файлу), `state`, `video`.
* **Команды**: `GET :81/protocal.csp?fname=net&opt=iot_conf&function=set&<параметры>`: `nozzleTemp2`, `bedTemp2`,
  `setFeedratePct`, `setPosition=<ось><абсолютные мм>`, `gcodeCmd` (так же ходит ползунок вентилятора: `M106 S..`),
  `print=/media/mmcblk0p1/creality/gztemp/<файл>`, `pause=1|0`, `stop=1`. Каждая команда приходит дважды.
* **Камера**: при `"video": 0` Creality Print берёт `http://<ip>:8080/?action=stream` (MJPEG).
* **Файлы**: FTP, пользователь `anonymous`, относительный `CWD mmcblk0p1/creality/gztemp`, `LIST` (список показывается,
  только если выглядит как вывод vsftpd), `STOR` - загрузка, `DELE` - удаление.
* **Обойдённые странности**: значение оси ровно 0 в `curPosition` навсегда блокирует панель движения после нажатия «Home»
  (поэтому отдаётся 0.01); Marlin отказывается от `G28 Z`, пока X/Y не отхоумлены (мост шлёт полный `G28`);
  `M114` в Marlin ждёт пустой буфер движений, поэтому во время печати не используется; после хоуминга прошивка отдаёт
  логическое Z, равное 0, поэтому позиция берётся из счётчиков шагов.

## Известные ограничения

* Вентилятор показывается только вкл/выкл; стрелки Z перевёрнуты для принтеров, у которых по Z двигается портал (а не стол),
  так как Creality Print предполагает подвижный стол - из моста это не исправить.
* Номер состояния «пауза» (5) - предположение; на других принтерах и прошивках не проверялось.
* Нет автоматического восстановления печати после перезапуска службы или принтера.
